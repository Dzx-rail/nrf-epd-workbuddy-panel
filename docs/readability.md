# 小屏可读性：实测结论

这些数字是在 400×300、1bpp 三色墨水屏上反复对照得出的，改动版式前先读，能省掉大量试错。

## 字号是硬约束，不是阈值问题

同一段中文在 9/10/11/12px 下各用 4 个二值化阈值（70/90/110/130）渲染，统计墨迹像素：

| 字号 | 阈值 70 | 阈值 130 | 差异 |
| --- | --- | --- | --- |
| 9px | 321 | 328 | +2% |
| 12px | 545 | 556 | +2% |

**阈值只影响 2% 的墨迹量，字号决定一切。** 主观判读同样一致：

- 9px：`晴`、`第`、`券` 糊成一团，数字 `16` 被读成 `1G`
- 10px：仍残缺
- 11px：勉强
- 12px：干净

结论：**中文最小 12px**，数字可 11px。版面不够时优先删内容，不要压字号。

## 三种颜色的正确画法

1bpp 打包时逐像素判定，抗锯齿边缘的处理方式决定了字形是「清晰」还是「发胖」。

**黑字（白底）** — 直接绘制。边缘灰度 >140 判白，不会扩张。

**白字（黑底）** — 覆盖率先转蒙版，阈值 **60** 再填白。若沿用 140，
细笔画（如「十」的横画）覆盖率约 50%，会被判成背景色而整条消失。

**红字** — 覆盖率先转蒙版，阈值 **110** 填纯红；同时把红色平面的判据收紧为
`r > 150 且 r - max(g,b) > 70`。

反面教材：早期判据是 `r > 160 且 r > g 且 r > b`，抗锯齿产生的浅粉边缘（如 `(255,205,205)`）
也被算作红色，字形向外各扩 1px，12px 汉字的相邻笔画随即黏连——「周」「剩」「地」「0」全部中招，
而黑字完全正常，导致问题被误判为字体缺陷。

阈值 110 偏细、85 偏粗，95 介于两者之间；具体取哪档取决于屏体与颜料，需上屏比对。

## 有些字只能换图标

`晴`（日 + 青）在 14px 高度内要塞进 5 条横画，平均每条不足 2 像素，**任何字体都无法分开**。
这类高密度字不要试图靠字号或加粗解决，改用几何图标：

| 天气 | 图标画法 |
| --- | --- |
| 晴 | 实心圆 + 8 条光芒 |
| 多云 | 太阳被云遮住一半 |
| 阴 | 云（三圆 + 矩形并集） |
| 小/中/大雨 | 云 + 1/2/3 滴斜线（用数量表强度） |
| 雷阵雨 | 云 + 闪电多边形 |
| 雪 | 云 + 三个十字 |
| 雾 | 四条横线 |

图标由线段与圆构成，与字体解耦，16px 下即可辨认。**实心优于描边**：
描边的云内腔只有 2~3 像素，反而糊。

## 字体选择

- 正文用黑体类（SimHei）：笔画均匀，12px 可读
- 小字用雅黑类（Microsoft YaHei）：笔画更细、字腔更开，同尺寸下不易黏连
- 混用是可接受的：不同列用不同字体，读者不会察觉，但能解决局部可读性
- 跨平台时按候选列表回退（SimHei → PingFang → Noto Sans CJK）

## 反锯齿之外的两个教训

**先看位平面，再看 RGB 预览。** 版面的真实呈现由 1bpp 位平面决定，
在 RGB 图上看着清楚的文字，打包后可能整条笔画消失。验证方式是重建位平面再放大检查。

**跳过刷新要有内容摘要。** 三色屏全刷约 15~20 秒并伴随闪烁，内容未变时不刷。
摘要需排除时间戳等易变字段，否则每轮都算「变了」，等于没做优化。
